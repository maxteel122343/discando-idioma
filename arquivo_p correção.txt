# 🎙️ Guia de Conversação Fluida em Tempo Real com a IA Linguo (Mãos Livres)

Este documento explica em detalhes como a funcionalidade de **conversação viva e contínua com a IA (Assistente Linguo)** está estruturada no código, por que ela funciona, o que pode quebrá-la provocando fallback robótico, e fornece uma **Análise Técnica Assertiva** para resolver os problemas em outras bases de código.

---

## 1. 🔄 Arquitetura de Conversação Bidirecional (Mãos Livres Contínuo)

> 💡 **Princípio Fundamental de Usabilidade:**
> - **NÃO exige clicar a cada fala:** O usuário **NÃO** precisa apertar botões repetidamente para enviar áudio ou fazer perguntas.
> - **Ativação Única:** O usuário clica **uma única vez** no botão **"Mãos Livres"** (ou no ícone de microfone contínuo) para autorizar o acesso ao microfone.
> - **Escuta Sempre Ativa:** A partir daí, o microfone fica aberto continuamente. O aplicativo escuta a voz do usuário em tempo real, detecta quando ele termina de falar, envia para a IA e responde em voz alta.
> - **Controle de Pausa Simples:** Se o usuário quiser parar ou interromper a escuta contínua, basta clicar novamente no botão **"Mãos Livres"** para pausar/desativar o microfone a qualquer momento.

O modo **Mãos Livres** permite que o usuário converse continuamente com a assistente Linguo enquanto estuda no discador, lê ebooks ou ouve músicas. O microfone permanece aberto sem exigir cliques repetidos.

```
┌─────────────────┐       🎙️ Fala do Usuário        ┌─────────────────────────┐
│                 │ ─────────────────────────────► │   SpeechRecognition     │

```

## 2. ⚡ Como Funciona e Por Que Funciona Perfeitamente

### A. Funcionamento do Ciclo (`AIVoiceAssistantCard.tsx`)
1. **Ativação Contínua (`isHandsFree = true`)**: Instancia o `window.webkitSpeechRecognition` com `continuous = true` e `interimResults = true`.
2. **Prevenção de Realimentação de Eco (Microfone ouvindo a si mesmo)**:
   - Assim que a fala do usuário é finalizada (`result.isFinal` ou debounce de término de pausa de 1.2s), o aplicativo faz `recognition.stop()`.
   - Isso garante que a voz emitida pelo alto-falante/alto-voz da assistente não seja escutada de volta pelo microfone, evitando loops infinitos e travamentos.
3. **Comunicação com Backend Seguro (`/api/chat-tutor`)**:
   - A requisição traz o texto falado + contexto do estudo (palavra atual no disco, tradução, idioma).
   - O backend utiliza `@google/genai` com `gemini-3.5-flash`.
4. **Retorno de Áudio sem Interrupção**:
   - A assistente fala utilizando `speakTutorSequence`.
   - Ao disparar o evento `onFinishedAll` (quando a IA encerra a fala), o microfone é **reativado automaticamente** (`recognition.start()`).

### B. Por Que Funciona
- **Zero Vazamento de Chaves**: A chamada Gemini ocorre no servidor Node.js/Express (`/api/chat-tutor`), eliminando erros de CORS, chaves expostas no cliente ou bloqueios de navegadores.
- **Resiliência a Erros de Conexão**: Se a API externa oscilar, o backend possui um *Fallback Conversacional Inteligente Local* que responde instantaneamente ao aluno com base em palavras-chave da palavra em estudo, sem interromper a fala do app.

## 3. ⚠️ Alterações que Poderiam Quebrar o Sistema e Gerar Fallback Robótico

Caso ocorram as seguintes alterações no código, o sistema pode degradar para falas robóticas ou travamentos:

1. **Retirar o `recognition.stop()` antes do áudio tocar**:
   - *Efeito*: O microfone escutará a própria voz da IA e responderá a si mesma indefinidamente em loop de eco.
2. **Acessar APIs de TTS ou Gemini diretamente do Client-side (Navegador)**:
   - *Efeito*: Gera erro `403 Forbidden` ou `429 Too Many Requests` no browser devido a chaves expiradas, falta de cabeçalhos CORS ou bloqueio de extensões/adblockers.
3. **Não aguardar o evento `onend` / `onFinishedAll` da síntese de voz**:
   - *Efeito*: As falas da IA vão se sobrepor (uma cortando a outra) ou o microfone ligará antes do áudio acabar.
4. **Falta de tratamento de nomes de vozes locais no Web Speech**:
   - *Efeito*: O navegador selecionará a primeira voz padrão do sistema operacional (frequentemente e.g. "Microsoft David" ou síntese genérica sem entonação), resultando em voz metálica/robótica.

## 4. 🛠️ Análise Técnica Assertiva para Resolver o Erro da Outra IA (Código Externo)

Analisando o documento recebido do outro código (*"Arquitetura de Integração de Voz: Neural Moderno (Google Cloud TTS) vs. Fallback Robótico (Web Speech API)"*), identificamos os **4 problemas raiz** que estão fazendo a outra aplicação cair no fallback robótico, acompanhados das **Soluções Assertivas de Código**:

### ❌ Erro Raiz 1: Chamada Direta da API de TTS pelo Navegador (Client-side REST)
*Sintoma*: A outra IA está fazendo `fetch('https://texttospeech.googleapis.com/v1/text:synthesize?key=' + key)` diretamente do navegador React/JS.
*Por que falha*: Navegadores bloqueiam chamadas diretas por política de segurança, e a API Key exposta no cliente expira rapidamente por cota/CORS ou é bloqueada por extensões (AdBlock/uBlock), acionando o erro 403/429.

#### 🎯 Solução para a outra IA:
Mover a síntese de voz para um **Proxy Endpoint no Backend Node/Express**:

```typescript
// No servidor backend (server.ts / express):
app.post("/api/tts", async (req, res) => {
  const { text, langCode } = req.body;
  const apiKey = process.env.GOOGLE_TTS_API_KEY || process.env.GEMINI_API_KEY;

  if (!apiKey) {
    return res.status(400).json({ error: "Chave Google TTS não configurada no servidor." });
  }

  try {
    const response = await fetch(`https://texttospeech.googleapis.com/v1/text:synthesize?key=${apiKey}`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        input: { text },
        voice: {
          languageCode: langCode || "pt-BR",
          name: langCode === "en-US" ? "en-US-Neural2-F" : "pt-BR-Neural2-A"
        },
        audioConfig: { audioEncoding: "MP3", speakingRate: 0.98, pitch: 1.05 }
      })
    });

    const data = await response.json();
    return res.json({ audioContent: data.audioContent });
  } catch (err) {
    return res.status(500).json({ error: "Falha na síntese do servidor" });
  }
});
```

### ❌ Erro Raiz 2: Seleção Deficiente de Vozes no Fallback do Web Speech API
*Sintoma*: Quando cai no Web Speech (`window.speechSynthesis`), a outra IA pega a voz padrão `voices[0]`, gerando som metálico de robô de 1995.

#### 🎯 Solução para a outra IA:
Implementar um **Filtro de Vozes Neurais/Naturais** no sintetizador do navegador:

```typescript
export function getBestNaturalVoice(langCode: string): SpeechSynthesisVoice | null {
  const voices = window.speechSynthesis.getVoices();
  const langPrefix = langCode.split('-')[0]; // ex: 'pt' ou 'en'

  const langVoices = voices.filter(v => v.lang.startsWith(langPrefix) || v.lang.replace('_', '-').startsWith(langPrefix));

  if (langVoices.length === 0) return null;

  // Busca prioritária por palavras-chave de alta qualidade nas vozes do SO
  const neuralVoice = langVoices.find(v => 
    v.name.includes('Google') || 
    v.name.includes('Neural') || 
    v.name.includes('Natural') || 
    v.name.includes('Premium') ||
    v.name.includes('Luciana') || // Voz natural de PT-BR no Windows/Mac
    v.name.includes('Felipe')
  );

  return neuralVoice || langVoices[0];
}
```

### ❌ Erro Raiz 3: Bloqueio de Áudio em Dispositivos Móveis (Blob vs Base64)
*Sintoma*: No iOS (Safari) e Android (Chrome), o áudio Base64 `data:audio/mp3;base64,...` não toca se a política de Autoplay não for liberada por evento de clique, travando a reprodução.

#### 🎯 Solução para a outra IA:
Utilizar um elemento de áudio reaproveitável destravado no primeiro clique do usuário:

```typescript
// Desbloqueia áudio HTML5 no primeiro clique/interação do usuário
let globalAudioCtx: HTMLAudioElement | null = null;

export function initAudioUnlock() {
  if (!globalAudioCtx) {
    globalAudioCtx = new Audio();
    // Toca um som mudo para autorizar reprodução automática
    globalAudioCtx.src = 'data:audio/wav;base64,UklGRigAAABXQVZFZm10IBIAAAABAAEARKwAAIhYAQACABAAAABkYXRhAgAAAAEA';
    globalAudioCtx.play().catch(() => {});
  }
}
```

### ❌ Erro Raiz 4: Falha no Sequenciamento de Áudio 연속 (Fila Sobreposta)
*Sintoma*: A resposta do tutor fala por cima da pergunta ou o microfone reabre enquanto a voz ainda está saindo.

#### 🎯 Solução para a outra IA:
Utilizar uma **Fila Assíncrona com Callback de Conclusão**:

```typescript
export function playAudioSequence(
  items: { text: string; langCode: string }[],
  onComplete?: () => void
) {
  window.speechSynthesis.cancel(); // Cancela falas anteriores pendentes

  let index = 0;

  function speakNext() {
    if (index >= items.length) {
      if (onComplete) onComplete();
      return;
    }

    const item = items[index];
    const utterance = new SpeechSynthesisUtterance(item.text);
    utterance.lang = item.langCode;
    utterance.rate = 0.96;
    utterance.pitch = 1.05;

    const bestVoice = getBestNaturalVoice(item.langCode);
    if (bestVoice) utterance.voice = bestVoice;

    utterance.onend = () => {
      index++;
      speakNext();
    };

    utterance.onerror = () => {
      index++;
      speakNext();
    };

    window.speechSynthesis.speak(utterance);
  }

  speakNext();
}
```

## 5. 📋 Checklist de Diagnóstico Rápido para a Outra IA

Se o outro aplicativo apresentar voz robótica novamente, execute este teste de 3 passos:

1. **[ ] Teste de Chave**: Verifique se a variável `GEMINI_API_KEY` ou `GOOGLE_TTS_API_KEY` está definida no arquivo `.env` do servidor (e NÃO no cliente).
2. **[ ] Teste de Filtro de Voz**: Abra o console do navegador e digite `speechSynthesis.getVoices().map(v => v.name)`. Verifique se há vozes `Google` ou `Natural` disponíveis no sistema.
3. **[ ] Teste de Ciclo Mãos Livres**: Verifique se a função do microfone faz `recognition.stop()` antes de chamar a síntese de áudio e `recognition.start()` no callback `onend` da fala.
## 6. 🔑 Configurando a Chave GEMINI_API_KEY no Servidor

Para utilizar o modelo Gemini com máxima capacidade conversacional:

1. Obtenha sua chave de API no Google AI Studio (https://aistudio.google.com).
2. Adicione a variável `GEMINI_API_KEY` no arquivo `.env` do projeto ou no menu de **Secrets/Configurações** da plataforma.
3. O servidor fará a inicialização preguiçosa (*lazy loading*) assim que a primeira solicitação for enviada.

## 7. 🎯 Resumo da Experiência do Usuário (Fluxo Mãos Livres)

1. **Ativação Inicial Única**: O usuário clica uma única vez no botão **"Mãos Livres"** para abrir o canal de áudio.
2. **Conversa Fluida sem Botões**: O usuário fala naturalmente a qualquer instante: *"O que significa esta palavra?"* ou *"Consegui discar!"* (sem precisar apertar nenhum botão para falar).
3. **Resposta Natural em Voz Alta**: A assistente Linguo processa a fala e responde imediatamente em voz alta e calorosa: *"Essa palavra significa 'Casado' em português! Muito bem, arraste ela para o centro!"*.
4. **Escuta Reaberta Automaticamente**: Assim que a assistente encerra a fala, o microfone volta a ouvir sozinho em segundo plano, pronto para o próximo comentário.
5. **Desativação a Qualquer Momento**: Quando quiser encerrar ou pausar a escuta, o usuário basta clicar novamente no botão **"Mãos Livres"** para fechar o microfone.
